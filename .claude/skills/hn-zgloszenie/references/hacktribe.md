# HackTribe: przebieg zgłoszenia

Źródła: przewodnik uczestnika HackNation [✔ Z2], regulamin [✔ Z4], opisy platformy w serwisach wtórnych [~ Z27]. Dostęp 2026-11-17. Adres instancji HackTribe dla HackNation 2026 nie jest podany publicznie; przewodnik odsyła do PDF „Tutorial HackTribe PL" w sekcji plików do pobrania na hacknation.pl. **Ściągnij go przed wyjazdem.**

## Co wiadomo

| Fakt | Pewność |
|---|---|
| HackTribe to platforma do rejestracji, zespołów, zgłaszania projektów i oceny przez jury | [~] |
| Strona do przesyłania rozwiązań działa od soboty 11:00 do niedzieli 11:00 | [✔] |
| Przy zakładaniu projektu podaje się: nazwę projektu, nazwę zespołu, repozytorium, numer stolika, wstępny opis rozwiązania | [✔] |
| Zadanie wybiera się przed sobotą 20:00. Później nie da się zmienić zadania ani założyć nowego projektu; istniejące zgłoszenie można edytować do niedzieli 11:00 | [✔] |
| Zespół może rywalizować najwyżej w dwóch zadaniach, z jednym projektem w każdym | [✔] przewodnik; ogłoszenia zewnętrzne mówią o dowolnej liczbie [~]. Potwierdź na Discordzie |
| Zgłoszenie finalne: wszystkie wymagane pola, prezentacja, materiały do weryfikacji zgodnie z wymaganiami zadania, konkretny opis, działające linki, krótkie demo (zalecane do 2 minut) | [✔] |
| Wysłanie rozwiązania oznacza akceptację regulaminu danego zadania | [✔] |
| Jeśli zadanie wskazuje inną platformę zgłoszeń, obowiązuje regulamin zadania | [✔] |
| W 2025 r. uczestnik relacjonował problemy z platformą zgłoszeń (fragment z LinkedIn, nie potwierdzono, że dotyczy HackNation) | [~] |

## Czego nie wiadomo (sprawdź na miejscu)

- Czy wideo wgrywa się jako plik, czy podaje link; limit rozmiaru pliku.
- Czy „prezentacja" to plik PDF/PPTX, czy link.
- Czy pola mają limity znaków.
- Czy zgłoszenie trzeba jawnie „wysłać", czy zapisany projekt jest zgłoszeniem.

Zapytaj o to na Discordzie w sobotę i dopisz odpowiedzi tutaj albo w `PROGRESS.md` repozytorium rozwiązania.

## Przygotuj z wyprzedzeniem (pola, które zwykle są potrzebne)

| Pole | Skąd wziąć | Kiedy |
|---|---|---|
| Nazwa projektu i zespołu | ustalone przy decyzji | sobota 13:00 |
| Link do repozytorium (publiczne) | GitHub | sobota 13:00 |
| Numer stolika | kartka na stole | sobota 13:00 |
| Wstępny opis (2–3 zdania) | sekcja 1 pliku decyzji | sobota 13:00 |
| Opis finalny (problem, rozwiązanie, wynik, wdrożenie) | pierwsze sekcje README | niedziela 09:00 |
| Link do wideo | `video_check.sh`, wgranie | niedziela 09:45 |
| Prezentacja (PDF) | `hn-pitch-final`, wersja 3-minutowa jako PDF | niedziela 09:30 |
| Link do działającej wersji (jeśli jest) | deploy | niedziela 09:30 |

Opis finalny trzymaj w pliku tekstowym w repozytorium (`docs/zgloszenie.md`) i wklejaj do platformy. Jeśli platforma padnie albo zgubi formularz, masz kopię, a README zawiera te same informacje.
